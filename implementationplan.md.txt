# Build a Telugu Voice AI Agent — Phase 1

## 1. Project Objective

Build a production-quality voice AI agent from scratch with **Telugu as the primary language**.

The agent must allow a user to speak naturally in Telugu, convert the speech into text using **Sarvam AI Speech-to-Text**, send the resulting text to **OpenAI's GPT API as the central reasoning/conversation brain**, receive a high-quality response, convert that response back into natural Telugu speech using **Sarvam AI Text-to-Speech**, and play the generated audio back to the user.

The architecture must be designed from the beginning so that **Hindi and English can be added later without rewriting the core system**.

The first implementation should focus heavily on Telugu quality.

---

# 2. Core Architecture

Implement this pipeline:

User microphone
↓
Audio capture
↓
Sarvam Speech-to-Text
↓
Transcript + detected/input language
↓
Conversation Manager
↓
User Custom Instructions
↓
System Agent Instructions
↓
OpenAI GPT API
↓
AI response
↓
Response Language Resolver
↓
Sarvam Text-to-Speech
↓
Audio playback
↓
User

The central intelligence/reasoning layer MUST be OpenAI.

Do not use Sarvam Chat Completion as the primary reasoning brain in this phase.

Sarvam should primarily handle:

1. Speech-to-Text
2. Text-to-Speech

OpenAI should handle:

1. Understanding the user's request
2. Conversation context
3. Reasoning
4. Following system instructions
5. Following user-configured agent instructions
6. Generating the final response
7. Deciding how the response should be phrased

# 5. TELUGU STT CONFIGURATION

Use Sarvam's current recommended Speech-to-Text API/model according to the official documentation.

For Telugu, use:

language_code = "te-IN"

Use the appropriate transcription mode for conversational Telugu.

The system should preserve natural Telugu speech rather than unnecessarily translating Telugu into English.

It must handle:

* Pure Telugu
* Telugu with English words
* Telugu with numbers
* Telugu with technical terms
* Telugu spoken conversationally
* Natural pauses
* Informal Telugu
* Common Telugu-English code mixing

Examples:

"నాకు రేపు హైదరాబాద్‌లో weather ఎలా ఉంటుందో చెప్పు"

"ఈ stock price ఎంత ఉంది?"

"నాకు ఒక email draft చేయి"

"Google Maps open చేయాలి"

Do NOT automatically translate these into English before sending them to the brain unless translation is explicitly required.

Prefer preserving the original transcript and language context.

Sarvam's current documentation identifies Saaras v3 as the recommended STT model and supports Telugu (`te-IN`) as well as code-mixed modes. Verify the exact current request parameters from the official documentation before implementation.

# 6. TELUGU TTS CONFIGURATION

Use Sarvam's current recommended Text-to-Speech model according to the official documentation.

For Telugu output:

language_code = "te-IN"

Use the appropriate Telugu-compatible voice/speaker.

Do not assume a speaker name without checking the current Sarvam documentation.

The TTS layer must support:

* Natural Telugu pronunciation
* Telugu-English code mixing
* Numbers
* Dates
* Common technical terms
* Natural conversational pacing
* Short conversational responses

Prefer streaming TTS if the current Sarvam API supports it reliably for this architecture.

The goal is to minimize:

User stops speaking
↓
STT processing delay
↓
GPT processing delay
↓
TTS generation delay
↓
Audio starts

The perceived response should feel conversational rather than like a traditional request/response API.

# 7. OPENAI AS THE CENTRAL BRAIN

OpenAI must be responsible for the actual intelligence.

The brain should receive structured context similar to:

{
user_message: "...",
detected_language: "te-IN",
conversation_history: [...],
system_instructions: "...",
user_agent_instructions: "...",
session_context: {...}
}

The exact API structure should follow the current official OpenAI API documentation.

Do not build a fake local reasoning layer.

Do not duplicate reasoning unnecessarily in the Sarvam layer.

The OpenAI model should understand Telugu directly.

Do not translate Telugu → English → GPT → Telugu unless technically required.

Direct multilingual reasoning should be preferred.

# 8. LANGUAGE BEHAVIOR — TELUGU FIRST

For Phase 1, Telugu is the primary conversational language.

Default behavior:

If the user speaks Telugu:

→ answer in Telugu.

If the user speaks Telugu + English:

→ respond naturally using Telugu-English code mixing where appropriate.

Example:

User:

"నా phone లో notifications రావడం లేదు, ఎలా fix చేయాలి?"

Good response:

"ముందుగా Settings లోకి వెళ్లి Notifications permission ON లో ఉందో check చేయండి."

Do not force unnatural pure Telugu translations of technical terminology.

The agent should sound like a natural Telugu-speaking assistant.

Avoid overly formal literary Telugu unless the user explicitly requests it.

Prefer conversational Telugu.

# 9. USER-CUSTOMIZABLE BRAIN INSTRUCTIONS

This is a CORE FEATURE.

Create a dedicated "Agent Instructions" / "Customize AI" flow.

The user must be able to enter instructions describing how they want the AI brain to behave.

Examples:

"నాతో ఎప్పుడూ తెలుగులోనే మాట్లాడాలి."

"Answer very briefly."

"Explain everything like I'm a beginner."

"Talk casually like a friend."

"Always give step-by-step instructions."

"Use Telugu but keep technical terms in English."

"Don't give long answers unless I ask."

"Act as my coding assistant."

"Whenever I ask something about trading, explain it with examples."

These instructions must be sent to the OpenAI brain as a dedicated instruction layer.

---

# 10. INSTRUCTION PRIORITY

Implement a clear instruction hierarchy.

Recommended priority:

1. Platform/System safety and application rules
2. Core Agent System Instructions
3. User's Custom Agent Instructions
4. Conversation context
5. Current user request

The user's custom prompt should strongly influence how the AI responds, but it must NOT be allowed to override higher-priority system or safety instructions.

Do not simply concatenate arbitrary user instructions blindly.

Create a dedicated instruction builder.

For example:

buildAgentInstructions({
coreInstructions,
userInstructions,
language,
responseStyle
})

This should produce a structured instruction context for the OpenAI model.

# 14. CONVERSATION MEMORY

Implement session-based conversation memory.

The agent should remember previous messages within the active conversation.

Example:

User:

"నా పేరు Sai."

Agent:

"Nice to meet you Sai!"

Later:

"నా పేరు ఏమిటి?"

Agent:

"మీ పేరు Sai."

Keep the conversation history in a structured format.

Do not send unlimited history forever.

Create a context management strategy.

The implementation should be capable of:

* trimming old messages
* summarizing older context if required
* preserving recent conversation
* preventing unnecessary token consumption

# 29. DEFINITION OF SUCCESS

The Phase 1 Telugu agent is successful when a user can:

1. Open the application.
2. Press the microphone.
3. Speak naturally in Telugu.
4. Sarvam correctly transcribes the speech.
5. OpenAI understands the Telugu request.
6. OpenAI follows the user's custom instructions.
7. OpenAI generates an appropriate Telugu response.
8. Sarvam converts that response into natural Telugu speech.
9. The user hears the answer.
10. The conversation continues naturally.
11. The system remembers the conversation within the active session.
12. Errors are handled gracefully.
13. API keys remain secure.
14. The architecture is ready for Hindi and English in later phases.

The final architecture should be modular enough that adding Hindi and English later primarily requires adding language configuration, voices, language-resolution rules, and tests rather than rebuilding the voice-agent core.

IMPORTANT FINAL RULE:

Do not claim that an integration works until you have actually tested the real API flow.

Use the official documentation as the source of truth whenever API parameters, model names, endpoints, SDK methods, authentication, streaming behavior, or limits are involved.
